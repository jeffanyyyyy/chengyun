# 可及性稽核與修正

針對 CHENGYUN.STUDIO（Obsidian）artifact 的內容章節做的稽核，以及一份可重複套用的修正。

Artifact：https://claude.ai/artifact/APm16Q6Cfn1UTGQnKZWetm

## 為什麼修正沒有直接發佈

稽核與修正都做完也驗證過了，但當時有另一個工作階段正在同時編輯同一個
artifact（做字級系統 `--fs-*`）。同一個 artifact 兩邊同時發佈，後發的會被擋下來，
而且每次重試都得先把對方 6000 行的最新版整份讀完才算「已檢視」——對方發佈的
頻率比讀完一輪還快，所以改成把修正留成腳本，誰有空檔誰套。

## 怎麼套

```bash
python3 tools/patch_a11y.py <來源 index.html> <輸出 index.html>
```

每一處都在指定的 CSS 規則區塊內替換，並斷言剛好命中一次。有任何一處沒命中就整個
中止，不會默默少改。所以不管對方又改了什麼，只要那幾條規則還在，就套得上去。

## 稽核結果

### 一、文字對比度（WCAG AA）

用 `tools/audit.py` 量。它會逐個分鏡走訪每一段文字，往上找出實際的背景色
（含半透明疊加），算出對比，再依字級判斷該用 4.5:1 還是 3:1。

修正前 **42 處不合格**，修正後 **2 處**。

| 用途 | 原本 α | 原本對比 | 改成 α | 改後對比 |
|---|---|---|---|---|
| `.film-hint`「點照片看介紹」 | .30 | 1.96 | .59 | 4.50 |
| `.film-count i` 膠卷計數 `/ 16` | .30 | 1.96 | .59 | 4.50 |
| 團隊章 `--dim`（眉標、註記） | .42 | 2.70 | .59 | 4.50 |
| `.frame-shot` 片格編號 | .32 | 2.76 | .47 | 4.78 |
| `.svc-num` 服務項目編號 | .35 | 3.15 | .45 | 4.52 |
| `.note` 各章註記 | .35 | 3.15 | .45 | 4.52 |
| `.flow b` 合作流程編號 | .35 | 3.15 | .45 | 4.52 |
| 作品集 `--pf-dim` 圖說 | .52 | 3.36 | .62 | 4.51 |
| `.faq-group` 分類標題 | .40 | 3.78 | .45 | 4.52 |

兩個取值上的判斷：

- **白字在深底取 .45**，因為 `.desc`、`.svc span`、`.field label` 這些本來就是 .45、
  實測 4.51 剛好過關。對齊網站自己已經在用的值，不是另外發明一個。
- **片格編號取 .47 而不是 .45**，因為每一格片格有自己的底色（`--b`，16 種）。
  對最亮的 `#101a0b` 來說 .45 只有 4.48，.47 才讓 16 種全部過（最低 4.78）。

**沒有動的 2 處**：`--pf-ghost`（作品集那兩行巨大的 CHENG / YUN），實測 1.41。
原始碼註解寫明「大標：在背景當底紋，不搶照片」，是刻意的裝飾性處理，
調高就毀了原意。

### 二、點擊目標（手機）

用 `tools/layout.py` 量。

膠卷下方的分頁圓點只有 **5×5 像素**，手機上幾乎按不到。

圓點本身不能放大：16 顆並排，390px 寬的螢幕塞不下更大的。所以改用一層看不見的
`::after` 把命中區撐到左右各半個間距、上下各 19.5px，版面一點都不動。

實際可按面積 **25 px² → 約 713 px²（28 倍）**。實測從圓點中心往上下 18px、
左右 6px 點擊都命中，而且左右各佔滿自己的間距、不會誤按隔壁那顆。

**查了但不是問題的**：

- 團隊章與作品集回報的「橫向溢出」是刻意的——膠卷是 `100vw` 滿版出血，
  緞帶面板本來就要飛出畫面。
- 表單欄位 39–42px 高、聯絡連結 24–27px 高、同意方塊 16×16，都低於 44×44，
  但都達到 WCAG 2.5.8 AA 的 24×24；同意方塊外面包著 `<label>`，實際可按範圍是整行。

## 本機怎麼測

```bash
python3 tools/serve.py <網站目錄> 8077
```

用內建的 `http.server` 會踩到兩個坑：

1. **不支援 Range 請求**，`<video>` 一律用 Range 取片段，影片永遠載不起來。
   `tools/serve.py` 補上了 206 回應。
2. **Playwright 內建的 Chromium 沒有 H.264 解碼**（`canPlayType('avc1')` 回傳空字串），
   所以 mp4 在測試環境播不起來，要另外轉一份 VP9/WebM 給它，交付檔不受影響。
